1 · Specify

/speckit-specify

Create a Feature Specification.

Feature ID
006-spreadsheet-style-editing

Feature Name
Spreadsheet-style Editing

Business Goal
Let a team member change any value directly in the meeting's action
list, saved straight away, like the spreadsheet they use today.

Business Value
FEH's requirement FR-005: an inline grid with autosave, so the
meeting is not slowed down by opening a form for every change.

Business Actors
Hotel team member

Business Capability
Fast Data Entry

Reference
FEH requirement FR-005; docs/mockup/01-meeting-screen.png; the
constitution's Technology Standards (HTMX for this spec only).

Builds On
003 to 005: the action list, its validation, and the counts that
must update after each change.

Functional Requirements

FR-001 The system shall let a person change any value of an action directly in
the meeting's list, saved without pressing a save button.

FR-002 The system shall show "All changes save automatically. Saved just
now." after each save.

FR-003 The system shall keep the last saved value and show the reason next
to the value when a change is not accepted.

FR-004 The system shall offer a blank row at the bottom of the list to add
an action in place.

FR-005 The system shall update the counts from 005 after each change.

Non-Functional Requirements

A change shall save in under one second (FEH NFR-004).

What It Looks Like On Screen
Changing Alex Wong's status in the list saves at once, the "Saved just
now" line appears, and the Overdue count changes when a due date moves.

Out of Scope
Keyboard shortcuts beyond normal Tab order.

Label every acceptance criterion AC-006-<nn>.
Generate the specification following the GitHub Spec Kit format.
Do not generate implementation details.
Do not generate source code.

    3. Under Value, paste the value, with no spaces or quotes around it.

    5. For DJANGO_SECRET_KEY, DEMO_ACCESS_CODE and AZURE_OPENAI_KEY, switch on Sensitive, so the value can't be read back later.

Risks and notes

  • Data resets only when you run seed_demo. The demo keeps changes until then; reset before each stakeholder session.
  • Anyone with the link and code can sign in as anyone. "Sign in as" is a workshop stand-in; Microsoft Entra ID replaces it in production. Keep the code to the people FEH names.
  • Synthetic data only (Principle IV): never load real FEH data into the demo, even briefly.
  • Cost: the demo fits Vercel's Hobby plan and a free Postgres tier for light use; check current limits before sharing widely. Vercel's own password protection for deployments is a paid feature, which is why the access code is built into the app.
  • Production is a different spec: Azure hosting, Azure Database for PostgreSQL and Entra ID stay out of scope and start from FEH's requirements, not from this demo.
