When something goes wrong

Gotchas

What happensWhat to do
The agent builds more than askedIt adds features "while it's there". Cite Principle XI (Keep It Small) and ask it to remove anything no criterion asks for.
The spec turns into a designScreens, buttons and databases creep into specify. Move them to the plan; the spec says only what users can do and see.
Clarify questions get guessedThe developer answers instead of FEH. Stop and ask the product owner; a guess becomes a wrong feature.
Someone edits code by handThe code and the spec drift apart. Amend the spec first, then let the agent change the code.
A spec is too bigIf it can't be built in half a day, split it before G1, not during implement.
A participant falls behind or driftsPaste the approved file from the Teams chat with the catch-up prompt on that slide. Nobody needs Git commands to catch up.
The database is in a strange stateRun uv run python manage.py seed_demo to reload the invented seed data.
Copilot credits are running lowSwitch to a mid-range model, start a new chat for the next spec, and close unneeded files. Finish the minimum line first; stretch specs are optional.
The browser won't recordAllow the microphone when Chrome asks (or in the site settings by the address bar). Recording only works on http://localhost or https, so open the app as localhost:8000, not by IP address.
"Transcribing…" never finishesLook at Terminal 1. With AI_PROVIDER=azure, a wrong value or a blocked network shows there. Set AI_PROVIDER=sample and restart to carry on.
A proposed item has empty fieldsThat's the spec working: values not in the fixed lists, or owners not in the hotel, are left empty for the chair. The item can't be confirmed until it's edited.
A key appears in code, a commit or the chatStop. Remove it, tell the facilitator so FEH can rotate the key, and keep it only in .env (Principle XVI).
Spec Kit commands vanish or changeNever re-run specify init in the project. Use specify self upgrade, and check specify init --help for flag changes.
